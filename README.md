# CSV Insight — 대용량 CSV / 로그 편집기

수 GB~수십 GB짜리 로그 CSV를 **통째로 메모리에 올리지 않고** 열어서 보고, 걸러내고, 고치고, 내보내는 도구입니다.
파이썬 표준 라이브러리만 사용하므로 설치할 패키지가 없고, **Windows·macOS·Linux에서 동일하게** 동작합니다.
UI는 로컬에서만 뜨는 작은 웹 서버 + 브라우저 화면입니다(외부로 나가는 통신 없음).

![CSV Insight 화면](docs/screenshot-light.png)

검색어에 맞는 행을 한 번에 책갈피로 남긴 모습 (행 번호가 노란색):

![책갈피](docs/screenshot-bookmarks.png)

## 빠른 시작

필요한 것: **Python 3.9 이상** + 아무 브라우저.
(파이썬 없이 쓰고 싶다면 아래 [실행 파일로 쓰기](#실행-파일exe로-쓰기) 참고)

### Windows

1. 이 폴더를 원하는 위치에 두고
2. `run.bat` 을 더블클릭 → 브라우저가 열리고 파일 선택 창이 뜹니다.
   * CSV 파일을 **`run.bat` 위로 끌어다 놓으면** 그 파일이 바로 열립니다.
   * 명령 프롬프트에서: `py -3 -m csvinsight C:\logs\app.csv`

### macOS

1. `run.command` 를 더블클릭 (처음 한 번은 우클릭 → 열기)
   * 터미널에서: `python3 -m csvinsight ~/logs/app.csv`
   * 실행 권한이 없다면 `chmod +x run.command`

### 어디서든

```bash
python3 -m csvinsight                 # 파일 없이 열고 UI에서 선택
python3 -m csvinsight app.csv         # 바로 열기
python3 -m csvinsight app.csv --port 8765 --no-browser
pip install -e .                  # 선택: csvinsight 명령으로 설치
```

주소에는 1회용 토큰이 붙습니다(`http://127.0.0.1:<포트>/?t=...`). 127.0.0.1에만 바인딩하고 토큰이
없는 요청은 거부하므로, 같은 네트워크의 다른 사람이 열 수 없습니다. 토큰은 같은 PC에서 도는
다른 프로그램이나 브라우저로 방문한 웹사이트가 이 서버를 두드리는 것까지 막아줍니다.

### 토큰 고정하기

기본값은 실행할 때마다 새 토큰이라 주소를 즐겨찾기에 둘 수 없습니다. 고정 주소로 안내해야
한다면 토큰을 정해 주세요.

```bash
csvinsight app.csv --token 정해둔값              # 최소 8자
set CSVINSIGHT_TOKEN=정해둔값 && csvinsight app.csv   # Windows
CSVINSIGHT_TOKEN=정해둔값 csvinsight app.csv          # macOS/Linux
```

명령줄은 같은 PC의 다른 사용자에게 보입니다(`ps`, 작업 관리자). 그래서 **환경변수 쪽을
권합니다.** 고정 토큰을 쓰면 실행할 때 그 사실을 알려줍니다 — 주소를 아는 사람은 그 PC에서
열려 있는 파일을 보고 고칠 수 있으니, 아무에게나 알려줄 주소는 아닙니다.

`--host` 로 다른 주소에 바인드해도 **접속은 `127.0.0.1` / `localhost` 로만 받습니다.**
다른 PC에서 붙는 용도가 아니라, 브라우저의 다른 탭에 떠 있는 웹페이지가 이 서버를
두드리는 것(DNS rebinding)을 막기 위한 검사입니다. 그래서 LAN IP나 도메인으로 접속하면
토큰이 맞아도 거부되고, 거부 사유를 토큰 문제와 구분해서 알려줍니다.

### 실행 파일(exe)로 쓰기

파이썬 설치가 곤란한 PC(사내 표준 이미지 등)에서는 단일 실행 파일로 만들어 쓸 수 있습니다.

* **직접 빌드**: `packaging\build_windows.bat` 더블클릭 → `dist\csvinsight.exe` (약 8 MB, 그 자체로 완결)
  * macOS/Linux: `packaging/build_macos.sh` → `dist/csvinsight`
* **CI로 빌드**: `.github/workflows/build.yml` 이 Windows·macOS·Linux 실행 파일을 만들어
  Actions 아티팩트로 올려줍니다. 태그를 밀거나 workflow_dispatch 로 직접 실행하면 됩니다.

exe 는 CLI와 UI를 모두 담고 있어 `csvinsight.exe app.csv`, `csvinsight.exe grep ...` 처럼 그대로 쓰며,
CSV 파일을 exe 위로 끌어다 놓아도 열립니다. (멀티프로세스 필터도 exe 안에서 동작합니다.)

## 무엇이 되나

**보기**

* 4.7 GB / 6천만 행 로그를 **한 번 인덱싱(약 20초)하면 이후에는 0.7초에 열리고**,
  스크롤은 어디로 튀든 1 ms 내외입니다 (아래 성능 참고)
* 가상 스크롤 그리드, 행 번호 고정, 열 너비 자동 맞춤 · 드래그 조절 · 왼쪽 고정 · 숨기기
* `level` / `severity` 열을 자동으로 찾아 ERROR·FATAL은 빨강, WARN은 주황으로 표시
* 라이트/다크 테마, 행 높이 3단계(줄바꿈 보기 포함)
* 값 분포·찾기·북마크·멀티 서치·열 패널은 **필요할 때만 꺼내는 서랍**입니다.
  기본은 닫혀 있어 표가 화면을 다 쓰고, 상단 **편의 기능** 버튼이나
  <kbd>Ctrl/⌘+B</kbd> 로 열고 닫습니다(마지막에 보던 탭을 기억합니다).
  패널 왼쪽 경계를 끌면 너비도 조절됩니다

**찾기**

* 상단 전체 검색(부분 일치 / 정규식 / 대소문자 구분) — Enter 한 번이면 파일 전체를 훑습니다
* 열 단위 조건 칩: 포함·일치·시작·끝·정규식·`>`·`≥`·`<`·`≤`·수치 범위·**시간 범위**·목록·빈 값·NOT
* "현재 결과 내에서" 를 켜면 이미 걸러진 결과 안에서 다시 좁혀 들어갑니다
* 값 분포(facet) 패널: 열 하나의 고유값 top 30 + 개수 + 막대, 값을 클릭하면 그 값으로 바로 필터
* 숫자 열이면 최소/최대/평균/숫자 셀 개수까지 같이 계산
* **여러 코어를 사용**합니다. 큰 파일은 자동으로 프로세스를 나눠 훑고, 결과는 단일 코어와 동일합니다
  (`--workers 1` 로 끌 수 있음)
* 정규식도 **반드시 포함돼야 하는 문자열**을 뽑아내 그 부분만 바이트 검색으로 건너뜁니다
  (`connection.*peer` → "connection"/"peer" 를 먼저 찾고 걸린 레코드만 파싱)
* 오래 걸리는 작업은 진행률이 뜨고 **취소** 버튼이 있습니다

**멀티 로그 서처 — 조건표 한 장을 통째로**

방화벽 정책표처럼 "조건이 여러 줄인 표"를 **멀티 서치** 패널의 엑셀 모양 입력칸에
붙여넣거나 직접 입력하면, 그 표 전체를 **한 번의 스캔**으로 로그에 맞춰 봅니다.

* 입력칸은 **스프레드시트**입니다. 셀을 직접 고치고, 줄·열을 더하거나 지우고,
  엑셀에서 복사한 블록을 커서 위치에 붙여넣을 수 있습니다
  (<kbd>Enter</kbd>/<kbd>↑</kbd><kbd>↓</kbd> 줄 이동, <kbd>Tab</kbd> 칸 이동)
* 열 너비는 **고정**입니다. 멋대로 바뀌지 않고, 열 경계를 끌면 조절되며
  경계를 더블클릭하면 그 열 내용에 맞춰집니다
* **각 열 머리에 그 열이 로그의 어느 열과 비교되는지가 드롭다운으로 붙어 있습니다.**
  자동으로 잡아주되 어디로 잡혔는지 항상 보이고, 틀렸으면 그 자리에서 바꿉니다.
  연결되지 않은 열은 노란색으로 표시됩니다
* 검색하면 **조건별 건수가 그 줄 오른쪽에 바로 찍힙니다.** 0건은 빨간색이고,
  건수를 클릭하면 그 조건에 맞는 행만 봅니다
* 패널 왼쪽 경계를 끌면 넓어집니다(너비는 기억됩니다)

* 한 줄 안의 칸들은 **AND**, 줄과 줄 사이는 **OR** — 정책표를 읽는 방식 그대로입니다
* `70.222.12.0/26` 같은 **CIDR**, `22, 23` 같은 **포트 목록**, 프로토콜, 포함·정규식·숫자 비교 지원
* 붙여넣는 즉시 **열 연결을 추측**합니다. 로그의 머리글을 그대로 읽어 쓰므로 열 이름이
  장비마다 달라도 됩니다 — `src_ip` / `srcip` / `source_address` / `sa` / `출발지IP` 모두
  `Source` 에 붙고, `Purpose` 같은 설명 열은 조건에서 빠집니다. 이름으로 판단이 안 서면
  실제 값을 표본으로 보고(그 열에 IP가 들어 있는지, `UDP`·`161` 같은 값이 보이는지) 고르며,
  머리글이 아예 없는 로그도 값만으로 연결합니다. 틀리면 드롭다운에서 바꾸면 됩니다
* **열 순서는 신경 쓰지 않아도 됩니다.** 내보내기 순서를 맞춰 뽑을 필요 없이 있는 그대로
  넣으면 됩니다. Palo Alto 트래픽 로그처럼 `Source address` 옆에 `NAT Source IP` 가,
  `Destination Port` 옆에 `NAT Destination Port` 가 나란히 있어도 **변환 전 열**을 고릅니다
  (정책표가 말하는 건 변환 전 주소니까요). 그래도 한 건도 안 걸리면 차선 후보로 바꿔
  표본에 대조해 봅니다 — 연결이 틀렸을 때 증상이 "모든 정책 0건"이라 그냥 두면
  '안 쓰이는 정책'으로 오해하기 때문입니다
* 결과는 **조건별 건수 목록**으로 나옵니다. 조건을 클릭하면 그 조건에 맞는 행만 보고,
  **0건인 조건은 빨갛게** — 실제로는 안 쓰이는 정책을 찾는 게 보통 목적입니다
* 행 번호 옆의 **파란 번호 배지**가 그 행을 잡은 조건 번호입니다
* 보고 있는 결과를 그대로 **책갈피로 표시**하거나 **별도 파일로 내보내기**
* 조건이 50개든 500개든 스캔은 한 번입니다. 각 조건을 가장 선택적인 값(포트·프로토콜) 아래
  묶어두고, 로그 행은 자기가 실제로 가진 값에 걸린 몇 개 조건만 검사합니다

![멀티 로그 서처](docs/screenshot-multisearch.png)

**책갈피 (Notepad++ 방식)**

* 찾기 패널의 **"모두 책갈피"** — 검색어에 일치하는 모든 행을 한 번에 책갈피로 표시 (Mark All)
* **책갈피 반전** — 표시된 행과 안 된 행을 서로 뒤집기
* **책갈피 행 삭제** / **책갈피 외 행 삭제** — 원하는 행만 남기거나 걸러낸 행만 지우기
* **책갈피만 보기**, **책갈피만 내보내기** — 표시한 행만 화면에 두거나 별도 파일로 저장
* <kbd>F2</kbd> 다음 책갈피, <kbd>Shift+F2</kbd> 이전, <kbd>M</kbd> 또는 <kbd>Ctrl+F2</kbd> 토글
* 셀 우클릭 → "이 값으로 모두 책갈피" 로 같은 값을 가진 행 전부 표시
* 6천만 행에서 60만 행을 표시하는 데 0.3초, 표시 안 된 5,940만 행을 지우는 데 0.7초,
  실행 취소도 0.3초 — 저장 전까지는 원본 파일이 그대로입니다

**고치기**

* 셀 더블클릭 또는 그냥 타이핑해서 편집, Enter는 아래로 Tab은 오른쪽으로
* 범위 선택 후 복사(TSV) / 붙여넣기(여러 셀 한 번에) / 아래로 채우기 / 비우기
* 행 삽입·복제·삭제, 열 추가·이름변경·순서변경·삭제
* **여러 열 한 번에 삭제** — 머리글에서 `Ctrl`/`⌘`+클릭(범위는 `Shift`+클릭)으로 고르거나
  열 패널에서 체크한 뒤 삭제. 몇 개를 지우든 되돌리기는 `Ctrl`/`⌘`+Z 한 번
* 찾기·바꾸기(정규식, 셀 전체 일치, 열 지정, 현재 결과만) — 수만 셀도 한 번의 실행 취소로 되돌아감
* 중복 행 제거, 앞뒤 공백 다듬기
* 실행 취소/다시 실행 100단계, 북마크(M), 행으로 이동
* **저장하기 전까지 원본 파일은 건드리지 않습니다.** 수정은 메모리 오버레이에만 쌓입니다

**내보내기**

* 저장(원본 덮어쓰기, 기본으로 `.bak` 백업 생성)
* 다른 이름으로 저장: 인코딩(UTF-8 / UTF-8+BOM / CP949 / CP932), 구분자, 줄바꿈(CRLF·LF) 선택,
  **현재 필터 결과만 저장** 옵션 — 5천만 행에서 에러 행만 뽑아 동료에게 보내는 용도

## 단축키

Windows/Linux는 `Ctrl`, macOS는 `⌘` 입니다. UI의 `?` 버튼에서도 볼 수 있습니다.

| 키 | 동작 |
|---|---|
| `↑ ↓ ← →` (`Shift`) | 셀 이동 / 범위 선택 |
| `Enter`, `F2` | 편집 시작 · 편집 후 아래 칸으로 |
| `Ctrl/⌘ + C`, `V` | 복사 / 붙여넣기 (여러 셀) |
| `Ctrl/⌘ + D` | 선택 범위 아래로 채우기 |
| `Delete` | 선택 셀 비우기 |
| `Ctrl/⌘ + Z`, `Shift+Z` | 실행 취소 / 다시 실행 |
| `Ctrl/⌘ + B`, `Esc` | 편의 기능 패널 열기·닫기 / 닫기 |
| `Ctrl/⌘ + F`, `Enter` | 찾기 패널 / 다음 결과 |
| `Ctrl/⌘ + G` | 행 번호로 이동 |
| `Ctrl/⌘ + S`, `O` | 저장 / 파일 열기 |
| `Ctrl/⌘ + +`, `-` | 행 삽입 / 선택 행 삭제 |
| `Ctrl/⌘ + 머리글 클릭` | 열 선택 (`Shift`+클릭: 범위) |
| `Shift + Delete` | 선택한 열 삭제 |
| `M`, `Ctrl/⌘ + F2` | 책갈피 토글 |
| `F2` / `Shift+F2` | 다음 / 이전 책갈피 |

## 명령줄에서도

UI 없이 쓸 수 있는 하위 명령이 있습니다. 배치 처리나 원격 서버에서 유용합니다.

```bash
python3 -m csvinsight info app.csv                     # 인코딩·구분자·행 수·열 미리보기
python3 -m csvinsight grep app.csv -w level=ERROR -o errors.csv
python3 -m csvinsight grep app.csv -c "timeout" --op contains
python3 -m csvinsight grep app.csv -e "user:\d{5}"     # 정규식
python3 -m csvinsight convert app.csv -o excel.csv --encoding utf-8-sig --newline crlf
```

## 성능

4코어 리눅스 컨테이너에서 측정했습니다. 두 파일 모두 8열짜리 로그입니다.

| 작업 | 161 MB / 200만 행 | 4.7 GB / 6,000만 행 |
|---|---|---|
| 처음 열기(인덱싱) | 0.6초 | 약 20초 (250 MiB/s 내외) |
| 다시 열기(인덱스 캐시) | 즉시 | 0.7초 |
| 임의 위치 200행 읽기 | 1.2 ms | 1.0 ms |
| `level = FATAL` 필터 | 0.4초 | 13초 |
| 검색 결과 모두 책갈피 | 0.01초 | 0.3초 |
| 책갈피 외 행 전부 삭제 | 0.03초 | 0.7초 (5,940만 행) |
| 삭제 실행 취소 | 0.01초 | 0.3초 |
| 인덱스 캐시 파일 | 15 MB | 458 MB (행당 8바이트) |

### 필터 종류별 (1.3 GB / 1,600만 행, 4코어 중 3개 사용)

| 조건 | 1코어 | 병렬 | 비고 |
|---|---|---|---|
| `level = FATAL` | 2.8초 | 1.6초 | 블록 리터럴 스캔 |
| 정규식 `user:\d{5}` | 8.5초 | 4.2초 | 정규식에서 "user:" 를 뽑아 선필터 |
| `host` 에 `host-0` 포함 | 32.3초 | 16.2초 | 리터럴이 너무 흔해 순차 파싱으로 자동 전환 |
| `latency > 900` (숫자만) | 34.4초 | 16.7초 | 선필터가 불가능해 전체 파싱 |

### 멀티 로그 서처 (1.1 GB / 1,600만 행 방화벽 로그, 정책 11줄)

| 작업 | 1코어 | 병렬(3코어) |
|---|---|---|
| 처음 열기(인덱싱) | 6.7초 | — |
| 정책 11줄 전부 대조 (848만 행 적중) | 68.6초 | 25.7초 |

조건 수는 거의 영향이 없습니다. 30만 행 기준 **조건 11개 1.6초, 조건 500개 1.5초** —
행마다 딕셔너리 조회 한 번으로 후보를 추리기 때문에, 조건이 늘어도 행당 비용은
그대로입니다. (버킷 키를 잘못 고르면 이야기가 달라져서, 표 전체에서 가장 적게
공유된 값을 키로 씁니다. 그 선택이 없으면 같은 500조건이 18.4초 걸립니다.)

정규식 가속 전후로 보면 `user:\d{5}` 는 161 MB 기준 9.3초 → 1.0초, `connection.*peer` 는
9.3초 → 0.8초입니다. 고정 문자열을 못 뽑는 `reset|expired` 같은 형태는 예전과 같은 전체 파싱입니다.

메모리는 파일 크기와 무관하게 **50 MB 내외**입니다. 인덱스는 디스크에 두고 메모리 맵으로
읽기 때문에, 전체 스캔을 한 뒤 RSS가 수백 MB로 보이더라도 그것은 OS가 언제든 회수할 수 있는
페이지 캐시이지 프로세스가 붙들고 있는 메모리가 아닙니다.

10 GB 파일이라면 처음 열 때 약 40~50초 인덱싱(진행률 표시와 취소 가능), 그 뒤로는 즉시 열립니다.

## 동작 방식

* **오프셋 인덱스** — 파일을 한 번 훑어 모든 레코드의 시작 바이트를 기록합니다. 따옴표 안의
  줄바꿈, `""` 이스케이프, 따옴표가 아닌 위치의 `"` 문자를 RFC 4180대로 구분하므로 로그에 섞인
  스택트레이스도 한 행으로 유지됩니다. 인덱스는 메모리가 아니라 `<파일>.csvidx` 에 바로 흘려
  쓰고 **메모리 맵으로 읽습니다**. 그래서 6천만 행이든 1억 행이든 프로세스 메모리는 그대로이고,
  두 번째부터는 스캔 없이 즉시 열립니다(파일 크기·수정시각이 바뀌면 자동 무효화).
* **편집 오버레이** — 바뀐 셀만 `{행: {열: 값}}`으로 들고 있고, 삭제 여부는 행당 1비트짜리
  비트셋, 위치 계산은 8192행 블록 단위 Fenwick 트리로 처리합니다. 그래서 5,940만 행을 지워도
  7 MB 남짓이고 실행 취소도 스냅샷 하나로 끝납니다.
* **블록 리터럴 필터** — `level = ERROR` 처럼 반드시 포함돼야 하는 문자열이 있는 조건은,
  레코드를 한 줄씩 파싱하는 대신 4 MB 블록을 통째로 `bytes.find` 로 훑고 걸린 지점만
  인덱스로 되짚어 파싱합니다. 같은 조건에서 6배 빠르며, 결과가 느린 경로와 완전히 같은지
  테스트로 검증합니다.
* **정규식 리터럴 추출** — 정규식을 파싱해 "어떤 매치든 반드시 포함하는 문자열"을 찾아
  같은 블록 스캔에 태웁니다. `reset|expired` 처럼 보장되는 문자열이 없으면 조용히 전체 스캔으로
  돌아가므로 결과는 항상 같습니다. 고른 리터럴이 너무 흔하면(첫 블록에서 40% 이상 등장)
  블록 스캔이 손해이므로 순차 파싱을 씁니다.
* **워커 프로세스** — 파일이 충분히 크고 수정 중이 아니면 행 범위를 나눠 여러 프로세스가
  같은 파일과 같은 메모리 맵 인덱스를 읽습니다. 시작 방식은 어디서나 `spawn` 이라 Windows에서도
  동일하게 동작하고, 프로세스를 못 띄우는 환경(샌드박스 등)에서는 자동으로 단일 프로세스로
  되돌아갑니다.
* **조건표 버킷 인덱스** — 멀티 서치는 조건 하나하나를 모든 행에 대보지 않습니다. 조건마다
  "표 전체에서 가장 적게 공유된 정확한 값"(보통 포트, 없으면 프로토콜) 하나를 골라 그 값
  아래에 등록해 두고, 로그 행은 자기가 가진 값으로 딕셔너리를 한 번 찾아 나온 몇 개 조건만
  검사합니다. IP는 CIDR을 정수 범위 두 개로 바꿔 비교하고, 주소 문자열→정수 변환 결과는
  캐시합니다(로그에서 주소는 수백 개가 수백만 번 반복되므로). 버킷 경로의 결과가 전수 검사와
  같은지는 테스트로 검증합니다.
* **작업(job) 큐** — 오래 걸리는 스캔은 백그라운드 스레드에서 돌고 UI는 진행률을 폴링합니다.
  어떤 스캔이든 중간에 취소할 수 있습니다.

## Windows / macOS 관련 메모

* **인코딩**: BOM이 있으면 그대로 따르고, 없으면 UTF-8 → CP949 → CP932 → CP1252 순으로 판별합니다.
  **저장할 때 원본 인코딩을 그대로 유지**하므로 BOM이 없던 파일에 BOM이 생기는 일은 없습니다.
  Excel에서 한글이 깨지면 내보내기에서 `UTF-8 (BOM 포함)` 또는 `CP949`를 고르세요.
* **줄바꿈**: 원본이 CRLF면 CRLF로, LF면 LF로 저장합니다(내보내기에서 변경 가능).
* **Excel이 파일을 열고 있으면** Windows에서는 덮어쓰기가 실패합니다. 이 경우 "다른 프로그램이
  파일을 잡고 있다"는 메시지를 보여주니 Excel을 닫고 다시 저장하세요.
* **경로**: UI의 파일 열기 창이 서버 쪽 디렉터리를 직접 탐색합니다. Windows에서는 드라이브 문자
  (`C:\`, `D:\`)가, macOS에서는 홈·데스크톱·다운로드·`/Volumes`가 바로가기로 나옵니다.
* macOS에서 `run.command` 가 "확인되지 않은 개발자" 로 막히면 우클릭 → 열기 를 한 번 해주세요.

## 대용량 파일을 다룰 때

* **디스크 여유**: 인덱스 캐시는 행당 8바이트입니다(1억 행 ≈ 800 MB). 원본 옆에 만들 수 없으면
  임시 폴더에 만들고, 그것도 막히면 메모리에 둡니다. 캐시를 아예 만들지 않으려면
  `python3 -m csvinsight open big.csv --no-cache` 로 실행하세요.
* **저장**: 저장은 파일 전체를 다시 쓰므로 같은 디스크에 원본 크기만큼 여유가 필요합니다
  (부족하면 저장을 시작하기 전에 알려줍니다). `.bak` 백업까지 켜면 두 배가 필요하니
  10 GB급 파일에서는 백업 체크를 끄거나 "다른 이름으로 저장"을 쓰는 편이 낫습니다.
* **원본을 건드리지 않는 작업 흐름**: 필터 → 책갈피 → "책갈피만 내보내기" 는 원본을 전혀
  다시 쓰지 않으므로 수십 GB 로그에서도 가장 빠릅니다.

## 알려진 한계

* 전체 정렬은 기본적으로 500만 행까지만 허용합니다(그 이상은 먼저 필터로 줄인 뒤 정렬).
* 중복 행 제거는 서로 다른 값 500만 개까지만 추적합니다(그 이상은 범위를 좁혀야 합니다).
* 정규식에서 고정 문자열을 뽑을 수 없는 형태(`reset|expired`, `[a-z]+` 등)는 전체 파싱이 필요합니다.
  가능하면 공통 문자열이 있는 형태로 쓰거나 열 조건을 먼저 걸어 좁히세요.
* 찾기·바꾸기와 열 통계는 아직 단일 프로세스입니다(필터·책갈피 표시·멀티 서치는 병렬).
* 멀티 서치는 IPv4만 압니다(IPv6 CIDR은 조건에서 빠집니다). 한 행이 여러 조건에 맞으면
  방화벽과 같이 **위에서 첫 번째로 맞는 조건**이 그 행을 가져갑니다.
* 붙여넣는 조건표는 2,000줄까지입니다.
* 한 번에 한 파일만 엽니다(탭/분할 보기는 아직 없음).
